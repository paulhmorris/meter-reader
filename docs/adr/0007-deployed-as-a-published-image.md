# Deployed as a published image, from the stacks repo

Where everything runs did not change — one host on the broker's LAN, for the reason ADR-0005 gives — but what is deployed there did. A push to `main` has GitHub Actions build the Dockerfile and push `ghcr.io/paulhmorris/meter-reader`, tagged `latest` and `sha-<short>`, and the host pulls that image rather than cloning this repo and building it. The Compose file that runs it lives in the `stacks` repo beside every other service on that host, where Komodo reads it and holds the secrets in the stack's environment. The Compose file here still builds from source, because that is what a developer wants and what proves the Dockerfile.

The image carries no configuration at all, so that anyone could run it: the app reads every value through `$env/dynamic`, the services through `process.env`, and both Sentry DSNs arrive at runtime like the rest. Unset, Sentry reports nothing and the app is otherwise unchanged. A build-time value would be baked into a published artifact and impossible to rotate without rebuilding, so CI builds the app against canary values and fails if any of them reaches the bundle — the property is cheap to hold and quiet to lose, since a `$env/static` import would break it without breaking anything else.

The cost is that a deploy is now two repos and a registry rather than a `git pull` on the host: the code that runs is identified by a tag in the `stacks` repo, not by a checkout, and rolling back means naming the previous `sha-` tag rather than checking out a commit — which is the same operation, one indirection further away. Migrations still run as a one-shot service the app waits on, and the database still lives in the `meter-reader_pgdata` volume, so the Compose project keeps the name that resolves it.
